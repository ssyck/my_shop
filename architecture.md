# Манифест Архитектуры Системы (MyNewAttemp Engine)

Документ фиксирует фундаментальные правила проектирования, структуру данных и протоколы взаимодействия между компонентами интернет-магазина. Любые изменения вносятся строго с акцепта Хозяина.

---

## 1. Базовые Постулаты и Стек (Вне изменений)
*   **Ванильный подход:** Никаких Docker-контейнеров, менеджеров Composer, сторонних тяжелых ORM и фреймворков. Только чистый контролируемый стек.
*   **Технологический базис:** Локальный сервер XAMPP, PHP (Strict Types), Ванильный JS (без JQuery), Bootstrap 5 (исключительно для верстки).
*   **Принцип детерминизма:** Код прозрачен до последнего байта. Система оперирует прямыми быстрыми вычислениями без избыточных слоев абстракции.
*   **Железное правило данных:** Ничего, что акцептовано системой, удалять нельзя. Физическое удаление архивных данных и уволенных сотрудников категорически запрещено.
*   **Стандарт найминга (Naming Convention):** Все названия папок, файлов, ключей в JSON, переменных в сессиях, флагов допуска и URL-параметров пишутся строго в нижнем регистре. В качестве разделителей разрешены только нижнее подчеркивание (`_`) и дефис (`-`). Капслок и CamelCase (заглавные буквы) категорически запрещены.
    *   *Правильно:* `auth_server`, `token_exchange.php`, `buh_report`, `gold-token`, `client_id`.
    *   *Неправильно:* `AuthServer`, `tokenExchange.php`, `BuhReport`, `goldToken`, `clientId`.

## 2. Модульная Структура Проекта (Два Кармана)

Система разделена на два изолированных независимых контура бэкенда, общающихся по протоколу OAuth 2.0 (Authorization Code Grant).

### Контур А: `auth_server` (Сервер Авторизации "Харон")
Отвечает за периметр безопасности, хранение реестра сотрудников и выдачу прав доступа. Работает в режиме "слепого автомата" по файловой структуре.

*   **Карман №1 (Статика):** Файл `app/data/staff.json`. Центральный реестр сотрудников. Уволенные сотрудники не удаляются, а переводятся в статус `"status": "fired"`.
*   **Карман №2 (Динамика):** Папка `app/data/tokens/`. В момент успешного входа Харон чеканит уникальный золотой токен и создает временный файл (например, `gold_token_xxx.json`), куда записывает слепок прав пользователя на 1 час.

### Контур Б: `my_shop` (Основной витринный магазин и Дашборд)
Отвечает за бизнес-логику каталога, заказов и выполнение внутренних скриптов.
*   Точка входа в админку: `public/admin.php`.
*   Магазин ничего не знает про пароли сотрудников. Он доверяет "золотому ответу" Харона, полученному по скрытому бэкенд-каналу связи через cURL.

## 2.1. Изоляция Персональных Данных (Защита ПДн / ФЗ-152)

В целях соблюдения законодательства о персональных данных и исключения рисков компрометации ПДн при аудите системы, вводится жесткое разделение системного паспорта и персонального сейфа.

1.  **Слепота Харона:** Сервер авторизации (`auth_server`) в файле `staff.json` хранит исключительно коммерческо-системные маркеры сотрудника (логин, пароль, UUID и плоский массив купонов, например `["cl"]` для курьера). Хранение серии, номера паспорта или водительских прав в общем реестре Харона категорически запрещено.
2.  **Шифрованный Сейф Магазина (`my_shop/app/data/secure_staff/`):** Персональные данные сотрудников, необходимые для автоматического формирования документов (путевых листов, контрактов), хранятся на стороне магазина в изолированной папке. Именем файла является неизменяемый `user_uuid` сотрудника в формате `snake_case`.
3.  **Криптографический заслон:** Содержимое файла сейфа (`usr_timestamp_rand.json`) шифруется встроенными средствами PHP (`openssl_encrypt`) с использованием `client_secret` приложения.

### Словесная структура расшифрованного блока ПДн курьера:
*   `passport_series` — Серия паспорта (4 цифры)
*   `passport_number` — Номер паспорта (6 цифр)
*   `passport_issued_by` — Кем выдан документ (текст)
*   `passport_issued_date` — Дата выдачи (гггг-мм-дд)
*   `passport_division_code` — Код подразделения (`xxx-xxx`)
*   `driver_license` — Серия и номер водительского удостоверения

4.  **Режим моментального снимка в памяти:** Расшифровка ПДн происходит под водой строго в момент генерации печатной формы документа. После вывода формы на экран память сервера очищается. На диске в открытом виде ПДн не существуют.


## 3. Протокол Авторизации и Безопасности (Сквозной Цикл)

1.  **Запрос:** Браузер запрашивает секретный адрес `my_shop/public/admin.php`.
2.  **Заслон №1:** Магазин видит отсутствие сессии, собирает параметры (`client_id`, `redirect_uri`) и перенаправляет браузер к Харону на `auth_server/authorize_core.php`.
3.  **Контроль брутфорса:** Харон выводит форму ввода. Счетчик неверных попыток пишется в сессию сервера. После 3-й неудачной попытки Харон обнуляет счетчик и жестко выкидывает пользователя на фронт магазина смотреть рекламу (`index.php?show_ads=true`).
4.  **Выпуск жетона:** При верном вводе Харон генерирует одноразовый временный "деревянный жетон" (`code`), связывает его со своим реестром и редиректит пользователя назад в магазин: `admin.php?code=XXXXX`.
5.  **Обмен на золото:** Магазин перехватывает `code` и под водой делает скрытый cURL-запрос на `auth_server/token_exchange.php`, передавая свой пароль приложения (`client_secret`).
6.  **Финал:** Харон уничтожает одноразовый `code`, сверяет секреты и отдает магазину JSON-пакет с постоянным токеном доступа и плоским списком купонов (аббревиатур) деятельности сотрудника. Магазин сохраняет их в сессию и очищает URL.

### Исправление Бага Выхода (Single Sign-Out):
Кнопка `[ ВЫХОД ]` в Дашборде запускает сквозное уничтожение сессий: сначала стирается локальная сессия в `my_shop`, после чего браузер отправляется на шлюз `auth_server/authorize_core.php?action=logout`. Харон принудительно удаляет файл золотого токена из динамического кармана и сжигает сессию сервера. Залипание прав исключено.

## 4. Концепция Лаконичных Купонов и Слепого Меню

Вместо громоздких многомерных массивов прав, доступы кодируются плоским списком коротких двухбуквенных аббревиатур-купонов. Аббревиатуры рождаются органически по ходу развития бизнеса.

### Базовые маркеры системы:
*   `ac` (All Access / God Mode) — Полный доступ ко всем узлам, автоматический пропуск.
*   `pt` (Product Tools) — Доступ к родительскому модулю "Товары" (Листинг, карточки).
*   `od` (Order Data) — Доступ к Учету заказов и очереди за день.
*   `ul` (Upload Logs) — Доступ к системному конфигуратору и менеджеру модов.
*   `ph` (Photo Handler) — Изолированный доступ только к медиа-архиву картинок.

### Конвейер Слепого Рендеринга:
Внедрен принцип: **Допуск к уровню меню открывает всё его подменю целиком.**
Если у пользователя в билете от Харона есть купон родительского модуля (например, `pt`), ванильный цикл PHP генерирует для него весь обвес вкладки. Если купона нет — блок кода выбрасывается из рендеринга на этапе сборки страницы. Внутренний роутер бэкенда дублирует эту проверку одной строкой через `in_array()`.

### Выруливание специфических ролей через PHP:
Если сотруднику нужен специфический узкий доступ (например, Фотограф по купону `ph`), PHP-скрипт `PhotoController.php` под водой полностью перестраивает рабочую область: не рендерит стандартный аккордеон, а запирает пользователя в изолированную "песочницу" файловой системы (`public/assets/media/products/`), давая доступ строго к файлам изображений и блокируя просмотр цен или остатков.

## 5. Технология Модификаций "Skyrim для Бизнеса"

Для расширения функционала без изменения кода ядра применяется плагинная система. Специфические инструменты (например, отчеты для Главбуха) упаковываются в ZIP-архивы и устанавливаются на лету.

### Структура ZIP-пакета модификации:
*   `manifest.json` — Паспорт мода. Содержит уникальный UUIDv4, название, имя автора, точку интеграции (`entry_mod`) и `required_flag` (аббревиатуру купона, который родится по ходу для этого мода).
*   `form.php` — Изолированная визуальная форма фильтров на чистом Bootstrap 5.
*   `handler.php` — Бэкенд-скрипт с тяжелыми вычислениями.

### Статусы кода:
При загрузке плагин проходит через `PluginValidator.php`, распаковывается в персональную папку по своему UUIDv4 (`storage/plugins/UUID/`) и прописывается в реестр со статусом **`draft`** (черновик / выключен).
При нажатии кнопки **"АКТИВИРОВАТЬ"** Хозяин переводит мод в статус `active`. Ванильное ядро динамически склеивает реестр активных модов со статическим массивом `SYSTEM_MENUS`, врезая новую кнопку в меню и вешая на нее защиту рожденного флага. Если код мода упадет с ошибкой, Хозяин за секунду переводит его обратно в `draft`, сохраняя стабильность ядра магазина.

## 6. Хронология Финансового Учета (Заказы)

Все акцептованные системой заказы записываются намертво в текстовые файлы формата JSON. Путь вычисляется математически на основе даты:
`my_shop/app/data/orders/YYYY/MM/YYYYMMDD_XXX.json`

Внутрь файла вшивается моментальный снимок (snapshot) истории на секунду покупки:
*   Данные покупателя и точные цены номенклатуры на момент акцепта.
*   Аудит-трейл: Неизменяемый UUID оператора (`operator_uuid`), текстовое имя сотрудника на тот момент времени (`operator_name_at_moment`) и токен, под которым совершена операция.

Это гарантирует, что даже если Вася Третий уволился и его токен стерт Хароном, при проверке файла заказа через два года Бухгалтер увидит точное имя того, кто применил безумную скидку. Скрипты отчетов прочесывают эти папки через быстрый ванильный `glob()`.
